# v0.21.0 升级说明

## 运行环境与兼容性

- Next.js 16.3.5、React / React DOM 19.3.0；Docker 构建、Web、维护工具和 PostgreSQL 工具统一使用 Node.js 24 LTS。裸机用户也应先升级 Node 至 24，再重新安装原生依赖、构建并重启。
- `middleware.ts` 迁移为 `proxy.ts`，保留语言 Cookie、旧语言链接和 safe-appearance 行为。保留 Webpack 以兼容当前 PWA 构建；没有启用 Cache Components 或 React Compiler。
- 升级 next-intl、next-themes、SQLite/PostgreSQL 驱动、IMAP/MIME 解析、图标、状态管理、验证码解压资源和 Worker 工具链等兼容版本。Worker/Bun 类型与 Next.js 的 Node/浏览器类型隔离，避免新版全局声明冲突。
- Tailwind 保留 3.4 系列并使用匹配的 tailwind-merge 2.6.1；Zod 保留 3.x，邮件和 SQLite 依赖采用原主版本的最新兼容发行。TypeScript 保留 5.9.3 的 JavaScript 编译器 API。ESLint 使用 Next.js 当前 React 插件支持的 9.x，迁移到 flat config 和独立 lint 命令。不强行引入会改变样式、校验或邮件协议行为的大版本。
- 修复 PWA 在 App Router 下未注册、无扩展名 vendor 文件被语言重写导致安装失败的问题；仅预缓存静态资源，邮件、API 和登录页面保持网络请求。国际化显式指定初始 UTC 时区，水合后使用浏览器时区，避免服务端与客户端环境不同产生警告和显示不一致。
- 角色 hook 直接派生当前会话角色，避免注销后保留旧角色；滚动节流允许首次事件立即执行。

## 镜像体积

- Next standalone 排除 TypeScript、Webpack、SWC、esbuild 等仅构建时使用的包；SQLite 原生绑定、sharp 图片优化及其运行库均保留。
- Web 与维护镜像使用 Debian slim + Node 24 二进制和必需系统库，不复制 npm/pnpm/Yarn。保留 CA 证书、tini、非 root 用户、健康检查、数据库迁移和维护命令。
- PostgreSQL 工具的 YAML 配置读取器在构建阶段打包，不再在运行镜像中通过 Debian 安装 nodejs/npm 及整套依赖。保留 PostgreSQL 18 工具、TLS、备份和恢复脚本。
- Docker 构建上下文排除本地代理目录和安全审计临时副本。
- Windows 本地 standalone 应用文件由约 103.5 MiB 降到约 54.8 MiB（不含单独复制的 public/static）。这不是 Docker 镜像大小；最终镜像需按相同架构、相同压缩口径比较 registry manifest 层大小。升级前 v0.20.17 Web 镜像压缩层合计：amd64 113.29 MiB，arm64 114.08 MiB。

## 验证与发布

采用现有验证脚本，重点覆盖生产构建、SQLite/PostgreSQL HTTP 业务、邮件协议、维护工具、语言切换和验证码；浏览器检查 hydration、主题及 Service Worker 注册。依赖 audit 和 peer 检查均须通过。

发布 workflow 使用 Node 24，独立执行 lint，继续在 amd64/arm64 原生 runner 构建并运行镜像冒烟检查；所有构建通过后才合并并更新镜像标签。PostgreSQL 工具镜像额外检查 Node 和打包后的配置读取器可运行。

保持原有 SQLite / PostgreSQL Compose 目录和数据挂载。升级前备份数据库及配套配置，再拉取整套同版本镜像，避免混跑。v0.20.17 之前的 API Key 摘要迁移注意事项仍见 [安全修复部署说明](security-fix-deployment.zh-CN.md)。
