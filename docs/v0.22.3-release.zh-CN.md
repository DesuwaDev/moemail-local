# MoeMail Local v0.22.3

减少每次更新的镜像下载量，并避免更新应用时重建数据库容器。镜像内容与功能不变。

## 背景

v0.22.2 与 v0.22.1 的镜像层对比显示：应用镜像每次更新需重新下载约 66.5 MB，其中 Node 运行时（43.8 MB）与系统依赖（3.7 MB）内容未变，只因 CI 每次从头构建导致层摘要变化；维护镜像约 66.7 MB、数据库工具镜像约 44.5 MB 同理。PostgreSQL 镜像仅一个空层摘要变化，但镜像 ID 随之改变，`docker compose up -d` 会因此重建数据库容器。

## 改动

- CI 使用存放在 GHCR 的层缓存（`buildcache-*` 标签，`mode=min`）：输入未变的层复用同一产物，摘要保持不变；维护镜像优先复用应用镜像的运行时基础层，二者共享 Node 与系统依赖层。
- 应用镜像将依赖（`node_modules`）与本版代码拆为两层；依赖未变时，更新只需下载代码与静态资源（约 5 MB）。
- PostgreSQL 与数据库工具镜像不再写入每次变化的提交号、版本标签与来源证明，构建时间取其输入文件最后一次修改的提交时间；输入不变时镜像保持一致，应用更新不会重建数据库容器。上游 PostgreSQL 基础镜像更新时照常更新。
- 系统依赖层按月强制刷新（`APT_SNAPSHOT`），确保安全更新按时生效；每月一次额外下载约 20 MB。

## 生效节奏

本版本首次建立缓存，仍为完整构建，PostgreSQL 容器会最后重建一次；自下一个版本起，更新只下载实际变化的层。

部署约定与维护包校验通过；已确认独立输出中的依赖符号链接均为内部相对链接，拆层后保持有效。发布流水线的镜像冒烟测试会实际启动各镜像并检查页面、静态资源与图片处理。

本版本不新增数据库迁移、配置项或依赖。
