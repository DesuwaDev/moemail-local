# MoeMail Local v0.21.5

本版本修复反向代理下登录回调使用内部地址的问题，并收紧公开接口的信息暴露。包含 v0.21.4 的 Cap 失败处理设置。

## 更新内容

- 登录和 OAuth 回调统一使用 `server.baseUrl`，移除内部监听地址和端口；HTTPS Cookie 的写入与服务端会话读取保持一致，不受伪造的转发主机头影响。
- 拒绝无法解析的站点地址，并更新五种语言的设置提示。
- 分享 API 和服务端页面在查询数据库前校验 token，异常字符和超长输入返回不存在，避免 PostgreSQL 因异常输入返回 500。保留现有链接、永久分享、附件及过期和撤销控制。
- 匿名健康检查只返回运行状态；数据库类型、配置版本和错误详情不再公开。详细配置诊断仍可在皇帝的运行配置面板查看，Docker 健康检查行为保持兼容。
- PWA 不再预缓存 42 个无用的 API 路由客户端占位文件，保留页面资源与缓存清理流程。

## 升级说明

无需新增数据库迁移。请确认 `server.baseUrl` 与浏览器访问的公网地址一致，包括 HTTPS 和非默认端口；无需设置 `NEXTAUTH_URL` 或 `AUTH_URL`。从 HTTP 切换 HTTPS 后需要重新登录，更换域名时也须更新 OAuth 服务商登记的回调地址。

自定义监控应使用健康检查的 HTTP 状态码与 `status` 字段；原数据库和配置诊断字段已移至受保护的运行配置接口。

## 验证

- 生产构建、Lint、TypeScript、五语言和配置校验。
- 真实 HTTP 后端上的登录、恶意转发头、HTTPS Cookie、服务端会话及 GitHub 授权跳转地址检查。
- SQLite/PostgreSQL 分享、异常 token、附件、永久与过期链接回归；PWA 生成结果检查。
- 发布流水线继续验证各镜像的 Linux amd64/arm64 构建与运行。
