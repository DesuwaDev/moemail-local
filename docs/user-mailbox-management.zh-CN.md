# 用户与邮箱管理

皇帝可在「用户」中按用户名、登录邮箱或名下邮箱搜索。切换「邮箱」可按地址定位邮箱及所属用户，包含已过期、停用和未分配用户的邮箱。邮箱列表每页 8 条、收发件每页 10 条，详情在受视口高度限制的窗口内展开。

## 邮箱与邮件

- 用户详情可打开收件箱和发件箱，搜索主题及通信地址，查看正文与附件、删除单封邮件。
- 邮箱可停用或恢复、独立控制收信/发信/分享、调整有效期或设为永久、删除邮箱。删除需要确认，关联附件和分享链接随之删除。
- 停用保留已有邮件，阻断普通用户与 API Key 的读取、收发和公开分享；皇帝仍可检查。暂停收信不影响原有邮件读取，暂停发信不影响收信。
- 分享链接同时检查当前邮箱状态与所有者的查看、正文、附件和分享权限，避免通过分享绕过限制。Mailu 同步撤销不再允许的发件身份，保留只发不收邮箱的发信能力；入站提交再次检查停用和收信开关。
- 正文继续使用原有隔离渲染及外部资源防追踪设置。后台不会额外预加载外部图片。
- 收发统计来自当前保存的邮件，包含过期或停用邮箱；删除后减少。历史配额用量保留，不因删除重置。已修复单邮箱统计的子查询错误关联，旧查询会把邮箱 ID 解析为内层邮件 ID，造成零计数。

## 角色、用户与资源

保留皇帝、公爵、骑士、平民四种角色。权限、常规配额、域名规则分栏并支持筛选和分页。新增读取正文、下载附件、删除单封邮件三项权限；读取/删除单封邮件仍要求邮箱查看权限。删除邮箱权限包含整个邮箱及关联邮件的删除能力。

用户详情可选择继承角色或单独允许/禁止权限、设置用户配额及域名方向。完整收发配额规则仍在「权限配额 → 收发配额」中按用户、角色、域名或具体邮箱配置。更新单个角色不会覆盖其他角色或收发配额。

皇帝可撤销其他普通用户的全部登录会话、停用全部现有 API Key/Webhook、撤销所有分享。会话撤销后仍可重新登录；密钥、Webhook 和分享的持续限制需同时修改对应权限。不会显示密码哈希、API Key 明文或 Webhook 密钥。

邮箱管理、正文/附件访问和资源撤销记入分页操作记录。记录仅含操作者、目标标识、动作与时间，不含邮件内容和密钥。修改与日志在同一数据库事务内提交。此记录不声称覆盖升级前的行为或其他旧管理入口。

## 权限边界与升级

新的 `/api/admin/*` 接口仅接受当前皇帝的登录会话。API Key、普通用户以及仅获授用户管理权限的其他角色均不可调用。沿用同源请求检查；邮件与附件查询绑定所属邮箱，不能混用 ID 读取其他邮箱的内容。

新增 SQLite/PostgreSQL 迁移 `0008_mailbox_management`，旧邮箱默认保持启用并允许收发/分享；新增字段无需手工填写。权限配置升级为版本 8，根据旧查看和删除权限继承新增能力。修正了用户权限覆盖入口误用旧版校验器、拒绝较新权限的问题。

生产环境沿用现有启动迁移流程。回退应用前应恢复升级前数据库与配置备份，因为旧程序不识别权限配置版本 8。

## 验证

- `pnpm build`、TypeScript、修改文件 ESLint、五种语言目录检查。
- `pnpm validate:admin-management`：隔离数据库从迁移 0007 升级，验证旧邮箱默认值、邮箱归属搜索、非零统计、分页、权限及 CSRF、正文/附件、禁用与恢复、收信、永久有效、资源撤销、操作记录和级联删除。
- 同一验证支持 `--postgres-url=...`，目标须为可丢弃的空数据库。
- 现有邮件策略兼容检查，以及 Mailu 模拟服务验证收发独立控制、停用撤销发件身份与原有 IMAP/SMTP 流程。
- 浏览器检查手机窄屏、竖屏、横屏和桌面布局；后台正文容器显式设置高度，避免 iframe 塌缩。
