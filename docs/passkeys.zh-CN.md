# 通行密钥（Passkey）

通行密钥让用户用指纹、面容或设备 PIN 代替密码登录。私钥保存在用户的设备或密码管理器里，服务器只保存公钥；通行密钥与站点域名绑定，钓鱼网站无法使用。

## 用户怎么用

- **添加**：个人中心 → 账户 → 登录安全 → 通行密钥 →「添加」，按浏览器提示验证指纹、面容或 PIN。默认名称为当前浏览器和系统（如「Chrome（Windows）」），可随时重命名。
- **登录**：登录页「使用通行密钥登录」，浏览器列出本站的通行密钥，选中并验证即可，无需输入用户名、密码或人机验证。
- **管理**：列表显示名称、保存位置（如 Google Password Manager、Apple Passwords、Windows Hello，按 AAGUID 识别）、「已同步 / 仅此设备 / 安全密钥」、添加时间和最近使用时间。每个账户最多 10 个。
- **删除**：删除后该通行密钥立即无法登录；已用它登录的会话不受影响，如设备丢失请同时在「设备与会话」中退出对应会话。支持 Signal API 的浏览器会尝试隐藏设备上的副本，其他情况需在设备的密码管理器中手动清除。若设备上仍保留已删除的通行密钥，登录时会提示「本站未登记此通行密钥」。

通行密钥是额外的登录方式，不会替代或删除密码与 OAuth 登录。

## 开关

个人中心 → 运行配置 → 登录与鉴权 →「启用通行密钥」（`auth.passkeys.enabled`，默认开启），保存后热加载，无需重启。关闭后：

- 登录页不再显示通行密钥按钮（隐藏而非置灰，与未配置的 OAuth 一致）；相关接口一律返回 `PASSKEY_DISABLED`，关闭前已发出、尚未完成的登录也会失败。
- 不能添加新的通行密钥，也不能用通行密钥做再次验证（改用密码或重新登录）。
- 已添加的通行密钥保留：没有通行密钥的用户在「登录安全」中看不到该入口；已有的用户会看到「已暂停」说明，仍可查看、重命名和删除。
- 已登录的会话不受影响。重新开启后，保留的通行密钥立即恢复可用。

旧版本配置文件没有该字段时按开启处理，维护与数据库工具镜像读取旧配置和备份不受影响。

## 部署要求

WebAuthn 只在安全上下文中可用，因此：

- `server.baseUrl` 必须是 **HTTPS 域名**（本地开发可用 `http://localhost`）。HTTP 域名、IP 地址（如 `https://203.0.113.9`）都无法使用通行密钥，界面会显示原因，登录页不显示通行密钥按钮。
- 用户必须通过 `server.baseUrl` 这个地址访问。通行密钥的 RP ID 取该地址的主机名，服务器只接受来自该源的验证；通过其他域名或端口访问时，管理面板会提示应使用的地址。
- 更换站点域名后，旧域名下创建的通行密钥无法在新域名使用，用户需用其他方式登录后重新添加。
- 不需要额外配置、外部服务或网络访问，验证完全在服务器本地完成，适合国内网络环境。

数据库自动迁移 `0010_passkeys`（SQLite / PostgreSQL），新增 `passkey`、`passkey_challenge` 两张表和 `login_session.verified_at` 列。

## 安全设计

- **强制用户验证**：注册和登录都要求 UV（指纹、面容、PIN 等），仅触碰不算通过；要求可发现凭据，以支持免用户名登录。不收集设备证明（attestation `none`），不获取设备型号等隐私信息。
- **一次性挑战**：每次仪式的挑战保存在服务端，5 分钟有效，验证时原子删除，重放、过期或串用均失败。添加和再次验证的挑战绑定当前用户与登录会话，登录挑战不能用于再次验证，反之亦然。
- **来源校验**：严格校验 origin 与 RP ID；对保存签名计数器的认证器，计数器回退（疑似克隆）会拒绝登录，计数更新使用比较并交换，防止并发重复使用。
- **敏感操作再次验证**：添加或删除通行密钥前，当前会话须在 10 分钟内登录或完成验证。可用已有通行密钥或当前密码验证；两者都没有的账户（如仅用 OAuth 登录）需重新登录。密码验证计入登录频率限制并受 scrypt 并发保护。重命名无需再次验证。
- **范围限制**：管理接口只接受浏览器登录会话，API Key 无权访问；同源校验与 JSON 内容类型检查沿用现有规则。登录挑战接口计入登录频率限制。被封禁的用户无法用通行密钥登录。
- **审计与管理**：添加、删除通行密钥与管理日志在同一事务写入。皇帝可在「用户 → 用户详情 → 登录」查看并删除指定用户的通行密钥（例如设备丢失时），不能代为添加。删除用户时级联删除其通行密钥和未完成的挑战；过期挑战在每次签发时及维护清理任务中清除。
- 使用 Passkey 登录的会话在「设备与会话」中显示登录方式为「通行密钥」。

## 验证

`pnpm validate:passkeys` 使用软件认证器（真实 P-256 密钥、CBOR 证明对象与 ECDSA 签名）覆盖注册、免用户名登录、再次验证、重命名、删除与审计、数量上限、级联删除，以及挑战重放、跨会话/跨用户挑战、过期挑战、错误 origin 与 RP ID、缺少 UV、签名篡改、用户句柄不符、计数器回退、他人凭据等拒绝路径。加 `--postgres-url=` 参数可在可丢弃的 PostgreSQL 数据库上运行。
