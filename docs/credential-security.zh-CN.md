# v0.21.2：API Key 与登录会话安全

## 使用方式

个人资料 → 接口密钥：新建密钥默认只读、30 天有效。可以选择邮件管理或完整权限，并填写已有邮箱的完整地址，将密钥限定到该邮箱。列表显示权限、邮箱范围和到期日期。

- 只读：查看邮箱、邮件、附件及额度；不允许发送、删除、创建或读取分享链接。
- 邮件管理：可管理邮箱、发送与删除邮件、管理分享链接，但不能管理系统配置。
- 完整权限：保留原有 OpenAPI 行为，权限仍受账号角色、用户覆盖及额度限制。
- 限定邮箱：邮箱列表与总数仅包含该邮箱；不能创建新邮箱，也不能管理系统配置。即使该邮箱被删除，密钥也不会变成全邮箱权限。

个人资料 → 账户 → 登录安全：点击“退出所有设备”并确认后，包括当前设备在内的旧登录凭据，在后续请求时失效。可以重新正常登录。API Key 不受影响，请在密钥管理中单独停用泄漏的密钥。

## 升级与兼容

SQLite、PostgreSQL 的 `0006_credential_security` 是新增字段迁移：用户增加会话版本，密钥增加权限等级与邮箱 ID。部署前按原流程备份，启动时执行迁移。旧 Key 保留完整权限、原有效期；旧 JWT 在第一次主动撤销前保持可用。数据库导入保留已有的权限限制及会话版本，避免导入导致权限扩大。

为兼容现有调用方，`POST /api/api-keys` 只传 `name` 时仍创建完整权限、365 天有效的 Key。新客户端应显式传入：

```json
{
  "name": "读取验证码",
  "accessLevel": "read",
  "mailboxAddress": "existing@example.com",
  "expiresInDays": 30
}
```

`accessLevel` 可选 `read`、`mail`、`full`；`mailboxAddress` 为空时覆盖自己的所有邮箱；有效期支持整数 1–365 天。已创建密钥的权限固定，需要调整时创建替代密钥并停用旧密钥。

会话撤销接口为 `DELETE /api/account/sessions`，只接受当前用户的会话认证，执行同源检查，不接受 API Key，也不接受指定其他用户 ID。

## 响应头与界面

应用统一设置 `frame-ancestors 'self'`、`X-Frame-Options: SAMEORIGIN`、`nosniff` 和跨站精简来源策略，阻止外站嵌套页面。同源嵌套、邮件独立沙箱、原有自定义脚本及样式继续保留。反向代理应避免覆盖这些响应头；之前把站点嵌入其他域名 iframe 的部署需调整集成方式。

复用原有 Dialog、Select、AlertDialog 和卡片样式；窄屏表单纵向排列，宽屏权限与有效期并排，弹窗按动态视口限制高度并可滚动。

## 针对性验证

先执行 `pnpm build`，然后 `pnpm validate:credential-security`，使用隔离数据库与本地 HTTP 服务验证升级兼容、权限隔离、过期停用、跨站拒绝、双会话撤销及重新登录。可用 `--postgres-url=...` 指定专用空测试数据库。`--keep-server` 仅用于本地界面验证，输出的是临时测试账号。

现有 `validate:api-key-migration` 同时检查导入时保留权限与会话版本。功能验证以这些实际边界为主，不增加重复的全量压力测试。
