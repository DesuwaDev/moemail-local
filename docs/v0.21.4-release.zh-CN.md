# MoeMail Local v0.21.4

本版本修复 Cap 拒绝访问后自动切换通用备用验证码的问题，并提供独立的失败处理设置。

## 更新内容

- 在「网站配置 → 人机验证 → Cap 失败处理」中，分别配置访问拒绝和原因不明的网络错误：直接失败、沿用通用备用或使用指定验证码。
- HTTP 401/403/429/451、明确屏蔽响应使用拒绝策略；跨域、超时、断连及无法解析的成功响应使用原因不明策略。脚本加载失败及明确服务故障仍使用通用备用。
- 指定渠道必须配置有效密钥，服务端只接受已配置渠道的有效令牌；不可用的指定渠道不会悄悄改用通用备用，已失败渠道不会被循环重试。
- 修复 Cap 失败时未捕获的 Promise 异常，并将请求超时覆盖到响应体读取。
- 失败处理区域独立折叠，修改策略无需展开地址和密钥表单；窄屏纵向排列、宽屏并排，补齐五种语言。

## 升级注意

无需新增数据库迁移。两项失败策略默认均为「直接失败，不回退」，已有配置缺少对应字段时也采用此默认值。需要保留网络异常时的自动备用行为，请明确将「网络错误／原因不明时」改为「沿用通用备用」。

浏览器无法可靠区分被 CORS 隐藏的地区屏蔽与普通断网；默认停止可避免因此自动回退。此设置控制验证码切换，严格的网站级地区封禁仍应由应用或入口网关执行。

镜像更新应在 Publish Docker Images 工作流全部成功后进行；沿用现有 SQLite 或 PostgreSQL 部署方式。

- 真实 Cap 组件的浏览器模拟测试：正常验证、403 停止、指定/通用备用、503 故障、网络中断和重试恢复。

- Lint、TypeScript、五语言检查、生产构建及部署契约检查。
