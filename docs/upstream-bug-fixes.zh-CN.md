# v0.21.1：上游邮件显示与通知问题修复

本次覆盖上游 #59、#85、#24/#81 对应的已确认问题，并改善 #67/#84 的通知失败处理；不涉及 Cloudflare Worker / Pages 部署。

## 行为变化

- 域名下拉列表限制在可用屏幕高度内，支持滚动和上下滚动按钮。45 个域名可滚动到最后一项。
- 纯 HTML 邮件在接收时生成纯文本，保留原 HTML；旧邮件在读取详情时按需补出文本，不批量重写历史数据。转换会解码 HTML 实体、保留段落边界，并忽略脚本和样式。
- 收信保存所有解析出的附件。附件二进制放在独立表中，与邮件和收信额度在同一事务提交；重复收信不会重复写附件，删除邮件/邮箱会级联删除附件。列表查询不读取附件内容。
- 私人邮件、邮箱分享、单封邮件分享均提供附件下载；下载继续验证所有权/权限或分享有效期，强制作为下载返回并禁止缓存和 MIME 嗅探。
- CID 内嵌 PNG/JPEG/GIF/WebP/AVIF/BMP 图片可显示。详情 API 新增 `attachments` 和 `inline_images`，原 `html` 保留不变。预览继续使用无脚本、无同源权限的 iframe 沙箱；每份图片在 API 中只传一次，客户端重复 CID 展开总量限制为 64 MiB，防止恶意邮件导致浏览器内存膨胀。其余附件仍可下载。
- 切换邮件时恢复与当前邮件匹配的 HTML/文本视图。

## Webhook

个人设置新增“纯文本通知摘要”，适合将通知转发到 Bark、Telegram 等有长度或格式限制的平台。摘要模式不发送 HTML，正文按 UTF-8 字节限制裁剪，并提供 `truncated` 标记；原始邮件不会被裁剪。默认正文上限 2048 字节，可在 256–65536 字节内设置，主题上限 256 字节。具体推送平台仍可能对标题、模板或最终请求有额外限制。

旧配置默认保留完整正文模式，避免破坏既有 Webhook 接口。保存后实际通知生效；测试按钮直接使用当前设置。启用摘要后，接收端模板应使用 `content`。

接收端返回 `success: false`、`ok: false` 或非零数值 `errcode` 时不会误报成功。不可重试的 4xx 和明确业务拒绝会直接返回失败；网络失败、408、429、5xx 仍按现有最多三次规则重试。响应体读取也受超时限制。界面显示最近一次实际通知的成功/失败及错误代码，测试失败也显示错误代码。

这里的“接受”表示接收端 HTTP/业务回执成功，不承诺第三方最终送达。没有新增持久化通知队列，进程退出或重试耗尽后的通知不会自动补发。

## 升级与数据

SQLite、PostgreSQL 均新增 `0005_message_attachments.sql`，使用新增表/列迁移，不删除或改写旧邮件。沿用现有启动迁移流程；手动部署可执行 `pnpm db:migrate` 后重启。附件在数据库内，现有全库备份和恢复会一起包含附件，不需要额外文件卷。

旧版从未保存的附件无法凭现有邮件记录恢复，需要重新导入原始邮件。恢复旧版本数据库备份后，仍应运行当前版本的数据库迁移再启动应用。

## 验证

`pnpm validate:message-content` 用独立临时数据库验证旧库升级、HTML 文本回退、Unicode 摘要、附件字节、重复收信、用户隔离、两种分享及过期控制、CID 数据、通知回执/重试/状态、级联删除。通过 `--postgres-url=...` 可在专用空 PostgreSQL 数据库执行相同检查；仅使用测试数据，不应指向生产库。

另检查五语言文案、TypeScript、ESLint、生产构建；浏览器检查长域名列表和沙箱内图片实际显示。
